# Depth Clock — Android App (Capacitor)

The complete Depth Clock wallpaper editor (single-file HTML) wrapped as a native
Android app, with:

- **Offline AI subject cutout** — the ISNet model + ONNX runtime are bundled in
  `www/imgly/` (no internet needed to scan photos)
- **Apply to Lock screen / Home screen / Both** — native `DepthAndroid` bridge in
  `MainActivity.java` sets the wallpaper via `WallpaperManager`
- **Live wallpaper service** — `DepthLiveWallpaperService.java` renders the saved
  wallpaper with a **ticking clock + date** on your lock/home screen
  (Preview → "Set as Live Wallpaper" opens the system picker)

## Build the APK (one-time setup)

Requirements: Node 18+, **JDK 21**, Android Studio Ladybug+ (Android SDK 35).

> JDK 21 is not optional: `android/app/capacitor.build.gradle` (generated by Capacitor 7)
> compiles with `sourceCompatibility 21`, and `compileSdk`/`targetSdk` are 35.

```bash
# 1. install the Capacitor CLI + runtime (local folder only)
npm install

# 2. copy the web app into the Android project
#    (also regenerates android/capacitor-cordova-android-plugins/, which is
#     git-ignored — skipping this step makes the Gradle sync fail)
npx cap sync android

# 3. open in Android Studio
npx cap open android
```

In Android Studio: **Build ▸ Build App Bundle(s) / APK(s) ▸ Build APK(s)**.
The debug APK lands in `android/app/build/outputs/apk/debug/`.

For a release build, create a keystore and sign via
**Build ▸ Generate Signed Bundle / APK**, or add a signing config to
`android/app/build.gradle`.

## Project layout

```
capacitor.config.json     appId com.depth.live.wallpaper, webDir www
www/index.html            the entire editor (single file)
www/samples/              showcase photos + precomputed cutouts (vault)
www/imgly/                offline AI model + runtime (subject cutout)
android/                  Capacitor-generated Android project + native code
  app/src/main/java/.../MainActivity.java             + DepthBridge (apply bridge)
  app/src/main/java/.../DepthLiveWallpaperService.java live ticking wallpaper
  app/src/main/res/xml/wallpaper.xml                   wallpaper descriptor
```

## Using the app

1. Browse the vault — scroll / drag / swipe; tap a poster to open it, or tap **+**
   to pick your own photo.
2. The AI scan separates the subject; tune the clock (font, ink, effects, format,
   date layer) in the bottom sheet.
3. Preview → choose **Lock screen / Home / Both** → **Apply**.
4. Optional: **Set as Live Wallpaper** for the ticking clock version, then pick
   "Depth Clock — Live" if the system shows a chooser.

## Fixed in this revision

- **Build failed at resource linking** — `values/styles.xml` referenced `@color/colorPrimary`,
  `colorPrimaryDark` and `colorAccent` but `values/colors.xml` did not exist. Added.
- **`DepthLiveWallpaperService` did not compile** — `Paint.CENTER_ALIGN` / `Paint.LEFT_ALIGN`
  are not Android constants; they are `Paint.Align.CENTER` / `Paint.Align.LEFT`.
- **Apply / Live never reached the native side** — the `DepthAndroid` interface was attached in
  `onStart()`, i.e. after Capacitor had already loaded `index.html`. `addJavascriptInterface()`
  only becomes visible to JS on the *next* page load, so `window.DepthAndroid` was undefined:
  "Apply" silently fell back to downloading a PNG and "Set as Live Wallpaper" stayed hidden.
  It is now attached in `onCreate()`, and the web app also re-checks for it for ~6s.
- **Live wallpaper not offered by the system** — added the required
  `<uses-feature android:name="android.software.live_wallpaper" />`.
- **Live wallpaper drew nothing until a visibility change** — the engine now also renders on
  `onSurfaceChanged` / `onSurfaceRedrawNeeded`.
- **Boot stalled on Google Fonts** — the font stylesheet was render-blocking, so a phone with
  no or slow connectivity sat on the splash for tens of seconds. It loads non-blocking now
  (first paint went from "blocked until the request resolves" to ~0.2s in a no-network test).
- **Silent failures** — `apply()` reports decode/IO/permission errors back to the UI
  (`window.__depthFailed`) instead of showing "Applied ✓" regardless.
- **Robustness** — `targets` is parsed with `JSONObject` instead of substring matching, a
  ProGuard keep rule protects the `@JavascriptInterface` bridge in minified release builds, and
  the instrumented test asserts the real application id.

## Notes

- The exported settings JSON and the live service share the same layout fields
  (clockX/Y, clockScale, ink, layout, fmt24, showDate, dateX/Y).
- The live service is intentionally a faithful *stub*: it re-renders the exported
  photo with a live system-font clock. Point-perfect web-font parity inside the
  live service is the natural next iteration (bundle the chosen TTF and load it
  via `Typeface.createFromAsset`).
